# fact-check

모든 경로는 프로젝트 루트 기준이다. 공통 정책은 아래 참조 파일을 원본으로 사용한다. `guidelines/source-policy.md`의 조사 폴더 전달 규칙을 읽고 `research_dir`와 `topic_slug`를 유지한다. 아래 날짜 경로는 기본값이며 추가 주제는 전달받은 slug 하위 조사 폴더에 저장한다.

## 실행과 입력

공식·커뮤니티 조사 뒤, 또는 초안 수정으로 새 주장이 생겼을 때 실행한다. `guidelines/source-policy.md`, 해당 날짜의 후보·공식·커뮤니티 파일과 존재하는 초안을 읽는다.

## 작업 순서

1. 본문에 들어갈 사실 주장을 ID 단위로 나누고 Fact/Community Opinion/Interpretation을 구분한다.
2. 웹으로 공식 근거를 재확인한다. 날짜·버전·출시·Preview/Beta·비용·OS·권한/API·설치·Before/After를 확인하거나 해당 없음 이유를 남긴다.
3. 출처끼리 충돌하면 버전·시각·범위를 비교한다. 해결 안 되면 미확인으로 두며 다른 AI의 답을 근거로 통과시키지 않는다.
4. 주장마다 확인/조건부/미확인/반박/해당 없음과 채택/조건 명시/삭제/보류를 판정한다. 코드의 문서 확인과 실행 테스트 여부를 구분한다.

## 결과와 실패

`research/YYYY-MM-DD/fact-check.md`에 주장별 근거 URL·판정·본문 위치·미해결 사항·작성 진행 가능 여부를 저장한다.
핵심 주장에 미확인·반박이 남으면 작성 보류. 주변 항목은 삭제·범위 축소 후 진행할 수 있다. 웹 접근이 없어 최신 조건을 확인하지 못하면 해당 범위는 미완료로 남긴다.
