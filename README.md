### 🔶 시스템 구조 및 실행 흐름

Codex가 `AGENTS.md`의 공통 규칙과 `daily-run.md`의 실행 지침을 읽고, 다섯 개의 Skill을 순서대로 수행하도록 구성했습니다.

```text
Codex 예약 작업 / 수동 실행
            ↓
      AGENTS.md
       공통 정책
            ↓
    prompts/daily-run.md
       실행 지침
            ↓
     topic-research
       주제 선정
            ↓
    community-research
      사용자 경험 조사
            ↓
       fact-check
        사실 검증
            ↓
       blog-writer
       블로그 초안
            ↓
  search-visibility-review
      검색 가독성 검토
            ↓
     HTML / 이미지 가이드
            ↓
       사용자 최종 검토
```

각 Skill은 이전 단계에서 저장한 조사 파일을 읽어 다음 작업을 수행합니다. <br/>
이를 통해 조사 결과와 작성 결과를 분리하고 필요한 단계부터 다시 검토할 수 있도록 구성했습니다.

<br/>

### 🔶 핵심 로직

**1) Skill별 역할 분리 및 작업 연결**

하나의 프롬프트에서 모든 작업을 처리하는 대신, 조사·검증·작성·검토 작업을 다섯 개의 Skill로 분리했습니다.

- `topic-research`: 주제 후보 탐색, 중복 확인 및 적합성 평가
- `community-research`: Reddit, GitHub 등 실제 사용자 경험 조사
- `fact-check`: 공식 자료를 바탕으로 주요 주장 검증
- `blog-writer`: 검증된 자료를 이용해 한국어 본문 및 SEO 메타데이터 작성
- `search-visibility-review`: 글의 검색 가독성과 근거 표현 검토

공통 작업 규칙은 `AGENTS.md`에서 관리하고, 세부 기준은 `guidelines/`로 분리했습니다.

<br/>

**2) 주제 선정 및 사실 검증**

단순히 최신 발표라는 이유로 주제를 선택하지 않도록 평가 기준을 구성했습니다.

- 개발 활용성, 접근 난이도, 관련성, 기존 방식과의 차이, 공식 근거, 최신성을 기준으로 100점 평가
- 점수 평가 전 실제 활용 가능 여부와 공식 자료 존재 여부 확인
- 공식 자료로 확인한 사실, 커뮤니티 의견, 분석 및 해석을 구분
- 핵심 정보가 검증되지 않으면 다음 작성 단계로 진행하지 않도록 작업 규칙 설정

이를 통해 매일 반드시 글을 생성하기보다, 작성할 가치와 근거가 충분한 주제만 선정하도록 설계했습니다.

<br/>

**3) 단계별 파일 관리 및 산출물 생성**

조사 단계마다 결과물을 Markdown 파일로 저장하고 후속 Skill이 동일한 조사 경로를 참조하도록 구성했습니다.

```text
research/YYYY-MM-DD/
├── topic-candidates.md
├── official-research.md
├── community.md
└── fact-check.md

posts/
├── drafts/       # 본문 · SEO · 이미지 가이드
├── previews/     # HTML 미리보기
├── assets/       # 생성 이미지
└── published/    # 게시 완료 글
```

파일 단위로 작업 결과를 남겨 이전 조사 내용과 작성 근거를 다시 확인할 수 있도록 했습니다.

<br/>

**4) Markdown 변환 및 이미지 처리**

Node.js 스크립트를 이용해 블로그 초안을 HTML로 변환하고 이미지 자료를 준비하도록 구성했습니다.

- `render-preview.mjs`: Markdown을 오프라인 HTML로 변환
- `prepare-images.mjs`: 이미지 배치 가이드 및 설명용 SVG 생성
- HTML 이스케이프와 링크 프로토콜 제한으로 위험한 코드 실행 방지
- 기존 원본과 생성 파일을 덮어쓰지 않도록 새 파일명 부여
- 외부 이미지의 이용 조건이 불명확하면 다운로드 및 사용 보류

<br/>

### 🔶 기술적 고려 사항

**1) AI가 생성한 정보의 신뢰성**

- **고려한 문제:** AI가 확인되지 않은 내용을 사실처럼 작성하거나, 커뮤니티 의견을 공식 사실로 일반화할 수 있습니다.
- **처리 방식:** 공식 문서 우선 확인, 정보 유형 구분, 핵심 주장 검증을 단계별 작업 규칙으로 정의했습니다.
- **한계:** Skill의 검증은 AI와 검색 도구의 수행 결과에 의존하므로 최종적인 사실 확인은 사용자가 진행합니다.

**2) 재실행 시 기존 산출물 손상 위험**

- **고려한 문제:** 동일한 날짜의 작업을 다시 실행하면 이전 초안이나 미리보기가 덮어써질 수 있습니다.
- **처리 방식:** 기존 조사 자료 보존을 작업 규칙에 포함하고 HTML·이미지 생성 스크립트에서는 중복되지 않는 파일명을 사용하도록 구현했습니다.
- **결과:** 스크립트를 반복 실행해도 기존 미리보기와 이미지 가이드를 보존할 수 있도록 구성했습니다.

<br/>

### 🔶 테스트 및 검증

자동화 과정에서 생성되는 파일의 형식과 안전성을 확인하기 위해 테스트 및 검증 스크립트를 추가했습니다.

**주요 검증 항목**

- Markdown의 HTML 변환 및 위험한 스크립트 처리
- 반복 실행 시 원본과 이전 생성 파일 보존
- SVG 생성 시 입력값과 XML 이스케이프 검증
- Skill 형식 및 프로젝트 내부 링크 검증
- 초안과 SEO 파일, 조사 폴더 사이의 연결 확인

<br/>

**Test Stack**

`Node.js Test Runner` · `Python`

```bash
node --test scripts/test-preview.mjs scripts/test-images.mjs
python3 scripts/validate-workspace.py
```

이 검사는 코드 및 산출물 구조를 대상으로 하며, 웹 정보의 사실 여부나 예약 작업의 성공까지 보장하지는 않습니다.

<br/>

### 🔶 아쉬운 점 및 개선 방향

**1) AI 기반 작업 검증의 한계**

현재 작업 흐름은 Codex가 프롬프트와 Skill의 규칙을 수행하는 방식입니다. 

따라서 모델의 응답과 도구 사용 환경에 따라 결과가 달라질 수 있습니다.

향후에는 각 단계의 필수 산출물과 검증 결과를 프로그램에서 확인하고 조건을 통과한 경우에만 다음 단계로 진행하도록 보완할 수 있습니다.

<br/>

**2) 예약 작업의 실행 안정성**

Codex 예약 작업과 Mac 전원 관리는 별도로 구성되어 있습니다. 

goguma를 이용해 Mac을 깨우더라도 Codex 작업의 성공까지 보장되지는 않습니다.

향후에는 작업 실행 여부와 오류를 더 체계적으로 기록하고 확인하는 방식으로 개선할 수 있습니다.

### 🔶 실행 방법

**1. 프로젝트 복제**

```bash
git clone https://github.com/hyeong-ing/ai-blog.git
cd ai-blog
```

<br/>

**2. Codex에서 프로젝트 실행**

Codex에서 프로젝트를 열고 다음과 같이 요청합니다.

```text
prompts/daily-run.md에 따라 오늘의 AI 블로그 초안을 준비해줘.
```

웹 검색 및 파일 쓰기 권한이 필요하며, `.agents/skills/`의 Skill을 사용할 수 있어야 합니다.

<br/>

**3. 예약 작업 설정 (선택 사항)**

Codex 앱에서 해당 프로젝트의 일일 실행을 별도로 예약할 수 있습니다.

macOS 전원 관리에 관한 상세 내용은 [전원 관리 설정 안내](config/morning-power/README.md)를 참고합니다.

자동화는 초안 작성과 자료 준비까지만 수행하며, 블로그 게시는 사용자가 직접 진행합니다.
