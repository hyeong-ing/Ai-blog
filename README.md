# AI 블로그 작성 자동화 프로젝트 

**AI의 변화를 조사하고 검증한 뒤, 사람이 검토할 한국어 블로그 초안을 만드는 로컬 작업 공간입니다.**

핵심 질문은 “어제와 비교했을 때 AI로 새롭게 할 수 있게 된 일은 무엇인가?”입니다. 새로운 발표와 함께 개발자의 반복 작업을 줄이는 Skill, Tool, Agent, MCP, Connector, Workflow를 살펴봅니다.

Codex는 조사·사실 검증·초안·검색 가독성 검토를 수행하고, 사용자는 최종 편집과 게시를 담당합니다. Mac에서는 goguma와 macOS 예약 서비스를 연결해 필요한 아침 시간에 컴퓨터를 깨워 둘 수 있습니다.

## 제공하는 기능

- 실제 웹 검색과 공식 자료를 우선하는 주제 선정·검증 정책
- 조사부터 작성까지 이어지는 Codex Skill 5개
- 한국어 본문, 별도 SEO 메타데이터, 이미지 가이드 작성 절차
- Markdown을 오프라인 HTML로 변환하는 도구
- 검증된 내용으로 설명용 SVG 개념도를 준비하는 도구
- Mac의 아침 깨우기·잠자기 방지·사용 상태에 따른 잠자기 구성 예시

이 저장소는 Codex가 읽고 실행하는 작업 지침과 보조 도구의 모음입니다. 복제만으로 글 작성이나 시스템 예약이 자동 설치되지는 않습니다. 개인 원고·조사 자료·로그·계정 정보와 과거 운영 이력은 포함하지 않았습니다.

## 전체 흐름

```text
주제 선정 → 공식 자료 조사 → 사용자 경험 조사 → 팩트체크
    → 한국어 초안 → SEO/AEO/GEO 검토 → 이미지 계획·HTML 미리보기
    → 사용자 검토 → 사용자가 직접 게시
```

기본 조사 범위는 최근 24~48시간이며, 필요하면 7일로 확장합니다. 아직 다루지 않은 유용한 Skill·Tool·Workflow는 출시 시점이 오래됐어도 후보가 될 수 있습니다.

적합한 주제가 없으면 선정 없음으로 끝냅니다. 핵심 사실이 확인되지 않으면 작성을 보류합니다. 직접 쓰지 않은 제품을 사용한 것처럼 표현하지 않고, 커뮤니티 의견을 제품의 사실로 일반화하지 않습니다. 로그인·업로드·게시를 자동화하지 않습니다.

## 시작하기

### 1. 저장소 복제

```sh
git clone https://github.com/hyeong-ing/ai-blog.git
cd ai-blog
```

### 2. Codex에서 프로젝트 열기

Codex에서 이 폴더를 작업 프로젝트로 열고 웹 검색과 프로젝트 파일 쓰기가 가능한지 확인합니다. [AGENTS.md](AGENTS.md)가 공통 규칙이며, 세부 정책은 `guidelines/`에 있습니다.

정식 Skill은 `.agents/skills/`에 제공됩니다. 새 환경에서 자동 인식되지 않으면 해당 `SKILL.md` 경로를 지정해 읽도록 요청합니다. `skill-staging/`은 대체 사본이며 정식 Skill이 우선입니다.

### 3. 수동으로 한 번 실행

Codex 채팅에 다음과 같이 요청합니다. 셸 명령이 아닌 대화 입력입니다.

```text
prompts/daily-run.md에 따라 오늘의 AI 블로그 초안을 준비해줘.
```

실제 단계와 이미지 자리 표시·미리보기 절차는 매번 [일일 실행 프롬프트](prompts/daily-run.md)를 읽어 적용합니다. 처음에는 산출물과 오류를 직접 검토한 뒤 예약을 연결하세요.

### 4. 필요한 경우 예약

Codex 앱에서 이 프로젝트의 일일 실행을 별도로 예약합니다. 예를 들어 오전 7:30에 위 프롬프트를 수행하도록 설정합니다. GitHub Actions나 API 키로 Codex를 호출하는 구현은 포함하지 않습니다.

로컬 예약이 파일을 사용하려면 컴퓨터가 켜져 있고 앱이 실행 중이어야 합니다. 계정·플랜·도구 권한과 사용량 제한은 사용하는 환경에서 확인하세요. [공식 예약 작업 안내](https://learn.chatgpt.com/docs/automations?surface=app)

## Mac 아침 전원 관리: 선택 사항

블로그 작성은 수동으로도 실행할 수 있습니다. 아래 전원 구성은 macOS에서 아침 로컬 예약을 사용할 때 연결하는 선택 기능입니다.

| 한국 시간 | 동작 | 담당 |
| --- | --- | --- |
| 07:20 | 잠든 Mac 깨우기 | goguma |
| 07:20~08:20 | 잠자기 방지 유지 | LaunchAgent + Python + `goguma run` |
| 07:30 | 별도로 등록한 글 작성 실행 | Codex 앱 |
| 08:20 | 유지 해제 후 조건부 잠자기 | 별도 LaunchAgent |

**goguma는 Mac을 깨우고 잠자기를 막는 오픈소스 도구입니다.** Codex에 글 작성 지시를 보내는 도구는 아니며, 블로그 작성 Skill과도 역할이 다릅니다. 이 구성에서는 goguma의 예약 기능과 CLI를 직접 사용합니다. [goguma 공식 저장소](https://github.com/junnam586/goguma)

08:20에 다음 조건 중 하나라도 해당하면 그날 자동 잠자기를 건너뜁니다.

- 최근 5분 이내 입력이 있음
- 앱이나 시스템이 잠자기 방지 신호를 유지함
- 사용 상태를 확인하지 못함

취소 뒤에 다시 강제로 잠재우지 않습니다. 이후에는 macOS의 기존 유휴 잠자기 설정이 적용됩니다. 입력 없이 화면만 읽는 상황을 완벽히 구분하지 못하며, Codex 작업이 08:20을 넘었다고 유지 시간을 자동 연장하지도 않습니다.

설치 사본 위치, 개인 경로가 없는 plist 예시, 로그 확인과 중지 방법은 [전원 예약 안내](config/morning-power/README.md)에 있습니다. Python 표준 라이브러리와 goguma daemon/helper가 필요합니다. 실제 예약 파일·인증 정보는 저장소에 넣지 마세요.

## 블로그 작성 Skill

| Skill | 역할 |
| --- | --- |
| `topic-research` | 기존 글 중복 확인, 다섯 주제 범주 탐색, 후보 평가·공식 조사 |
| `community-research` | 실제 사용자 경험 조사와 인용 가능 여부 판단 |
| `fact-check` | 주장별 공식 근거 확인, 조건·미확인 사항 정리 |
| `blog-writer` | 검증된 자료로 한국어 본문과 SEO 메타데이터 작성 |
| `search-visibility-review` | 검색·질의응답·AI 인용 관점의 가독성과 정책 검토 |

SEO/AEO/GEO는 제목·요약·본문의 명확성과 근거를 점검하는 절차입니다. 검색 순위나 AI 인용을 보장하는 기능은 아닙니다.

## 파일 구조

```text
.agents/skills/            정식 Skill 5개
AGENTS.md                  프로젝트 공통 규칙
guidelines/                주제·출처·편집·검색·이미지 정책
prompts/daily-run.md        매일 실행할 작업 절차
templates/                 본문과 사용자 검토표
topics/                    빈 후보·게시 이력 양식
config/morning-power/      전원 관리 안내와 plist 예시
scripts/                   전원 관리·HTML·이미지·검사 도구
skill-staging/             Skill 대체 사본
```

사용 중 아래 자료가 로컬에 생성됩니다. 기본적으로 Git 업로드에서 제외합니다.

| 경로 | 생성 자료 |
| --- | --- |
| `research/YYYY-MM-DD/` | 후보·공식 조사·커뮤니티·팩트체크. 추가 주제는 slug 하위 폴더 |
| `posts/drafts/` | 본문, `-seo.md`, `-image-guide.md` |
| `posts/previews/` | 최종 Markdown에서 변환한 HTML |
| `posts/assets/` | 실제 생성한 이미지 |
| `posts/published/` | 사용자가 게시 완료를 알려준 글 |

공개용 `topics/`는 빈 양식으로 시작합니다. 사용 후 개인 주제 이력이 생기면 푸시 전 변경 내용을 확인하세요. 이미 추적 중인 파일에는 `.gitignore` 규칙이 소급 적용되지 않습니다.

## 미리보기와 이미지 도구

Node.js 20 이상이 필요하며 변환에는 npm 설치·서버·네트워크가 필요 없습니다. 다음 예시의 날짜·주제는 실제 경로로 바꿉니다.

```sh
node scripts/prepare-images.mjs research/YYYY-MM-DD/topic/image-plan.json
node scripts/render-preview.mjs posts/drafts/YYYY-MM-DD-topic.md
```

이미지 도구는 외부 이미지를 자동 다운로드하지 않습니다. 저작권·이용 조건이 불명확한 이미지는 사용을 보류하고, 설명용 개념도는 실제 제품 화면과 구분합니다.

HTML 변환기는 원고의 실행 가능한 HTML과 외부 이미지 로딩을 차단합니다. 기존 본문·SEO와 이전 HTML을 덮어쓰지 않으며, 생성된 HTML은 브라우저에서 오프라인으로 읽을 수 있습니다.

## 검사

Python 3.10 이상, Node.js 20 이상을 권장합니다. 실제 Mac 전원 관리는 macOS와 호환되는 goguma 설치가 별도로 필요합니다.

```sh
node --test scripts/test-preview.mjs scripts/test-images.mjs
python3 scripts/validate-workspace.py
```

검사기는 Skill 형식, 로컬 링크, 본문·SEO 쌍, 조사 폴더 연결을 확인합니다. 실제 웹 사실·글 품질·검색 노출·예약 실행 성공은 별도 검토 대상입니다. 개인 콘텐츠가 생긴 뒤에는 그 콘텐츠의 구조 오류도 보고할 수 있습니다.

## 사용자가 담당하는 일

- 실제 제공 조건·비용·권한과 중요한 출처 재확인
- 초안의 문체·인용·이미지 검토
- 플랫폼에 맞는 최종 편집과 직접 게시
- 게시 후 실제 URL·게시일을 기록하도록 알리기

오전 10시 게시 전 초안 검토를 목표로 활용할 수 있지만, 매일 글 생성이나 완료 시각을 보장하지 않습니다. 인증 정보, Codex 계정 파일, 원고·조사 자료와 실제 시스템 로그는 공개 커밋에 포함하지 마세요.

## 외부 구성 요소

HTML 변환기에 포함된 Marked의 라이선스와 출처는 `scripts/vendor/marked/`에 보존돼 있습니다. goguma와 Codex는 이 저장소에 포함되지 않는 별도 도구입니다.
